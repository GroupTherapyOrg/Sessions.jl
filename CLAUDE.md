# Sessions.jl Developer Guide

A reactive notebook IDE built with Therapy.jl, targeting full Pluto.jl feature parity.

## 🚨 CRITICAL ARCHITECTURE PRINCIPLES

Sessions.jl is a **pure Therapy.jl component**. It must be embeddable into any Therapy.jl webapp.

### Rule 1: ZERO Raw JavaScript in Sessions.jl

**NEVER write JavaScript string literals in Julia code.**

| ❌ WRONG | ✅ CORRECT |
|----------|-----------|
| `sessions_script()` with 700 lines of JS | Therapy.jl islands, signals, channels |
| `:onclick => "jsFunction()"` | `:on_click => () -> julia_fn()` |
| Manual DOM manipulation | Server signals + `data-server-signal` |
| Custom WebSocket code | Therapy.jl channels |

The ONLY JavaScript should be:
1. In Therapy.jl itself (infrastructure)
2. Generated by Therapy.jl (hydration scripts)
3. External library initialization via Therapy.jl's `ExternalLibrary` pattern (TODO)

### Rule 2: Unified Event Handler Syntax

Use `:on_click`, `:on_change`, etc. everywhere. Therapy.jl handles the difference:
- SSR components: Renders as `onclick` HTML attribute
- Islands: Compiles to Wasm event handler

**NEVER** use `:onclick` (lowercase) directly - let Therapy.jl normalize.

### Rule 3: Sessions.jl = Therapy.jl Component

Sessions.jl notebooks must be embeddable:

```julia
# In any Therapy.jl app
using Therapy, Sessions

function MyApp()
    Div(:class => "my-app",
        Header("My App"),
        # Embed a Sessions notebook as a component
        Sessions.NotebookView(notebook_id = some_id),
        Footer()
    )
end
```

This means:
- No global state assumptions
- No hardcoded routes
- Components accept props like any Therapy.jl component

### Rule 4: CodeMirror via Therapy.jl External Library Pattern

CodeMirror is an external JavaScript library. Therapy.jl needs an `ExternalLibrary` pattern:

```julia
# TODO: Add to Therapy.jl
CodeMirrorEditor = external_library(:CodeMirror) do props
    # Therapy.jl generates minimal JS to init the library
    # and provides hooks for lifecycle events
end
```

Until this exists, CodeMirror init is the ONE exception where JS is allowed,
but it should be isolated and minimal.

### How It Should Work (Target Architecture)

| Feature | Implementation |
|---------|---------------|
| Cell state display | `data-server-signal="cell_state_{id}"` auto-updates |
| Cell output display | `data-server-signal="cell_output_{id}"` auto-updates |
| Run button | Island with `:on_click` → channel message |
| Code editor | Therapy.jl ExternalLibrary pattern for CodeMirror |
| Dark mode | Island (already done: DarkModeToggle) |
| Add/delete cell | Channel messages, server updates signals |
| Dirty indicator | Island local state |

### Current State (Needs Refactoring)

Currently `sessions_script()` has ~700 lines of raw JavaScript handling:
- CodeMirror initialization ✓ (necessary, but should use Therapy.jl pattern)
- Signal subscriptions ✗ (should be automatic via data-server-signal)
- Event handlers ✗ (should be islands or channels)
- DOM manipulation ✗ (should be server signals)
- State tracking ✗ (should be islands)

**Priority refactoring:**
1. Move signal subscriptions to `data-server-signal` attributes
2. Create CellEditor island for interactive editor state
3. Use channels for all commands (execute, add, delete)
4. Eliminate manual DOM manipulation

## Therapy.jl Patterns Used

### Server Signals (Per-Cell)

Each cell has its own signals for fine-grained updates:

```julia
# Signal naming convention
cell_state_{uuid}   # "CELL_IDLE" | "CELL_QUEUED" | "CELL_RUNNING" | "CELL_ERROR"
cell_output_{uuid}  # HTML output string
cell_runtime_{uuid} # Execution time in ms

# Server updates signal → auto-broadcasts to subscribers
function set_cell_state!(cell_id::UUID, state::CellState)
    set_server_signal!("cell_state_$(cell_id)", string(state))
end
```

### Channels (Commands)

```julia
# Client sends command
TherapyWS.sendMessage('execute', {notebook_id, cell_id, code})

# Server handles
on_channel_message("execute") do conn, data
    # Execute cell and update signals
end
```

### SPA Navigation

Sessions.jl works with Therapy.jl's client router:
- `therapy:router:loaded` event fires after SPA navigation
- `TherapyRouter.onNavigate(callback)` registers post-navigation hooks
- CodeMirror reinitializes after route changes
